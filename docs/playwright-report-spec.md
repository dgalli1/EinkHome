# Playwright-style HTML report — feature spec

Reference: `/tmp/playwright-ref/playwright-report/index.html`, generated by
`@playwright/test` 1.62.1 (4 tests: 1 passed / 1 failed / 1 flaky / 1 skipped,
one with a retry, one with a screenshot attachment). Inspected live in
Chromium (dark Primer theme). Goal: a 1:1-style HTML report for the EinkHome
bookshelf e2e suite, where "test steps" = our per-action framebuffer
screenshots (Playwright's steps + screenshots + errors, adapted).

## Feature inventory of the reference report

### 1. Architecture
- Fully static folder: `index.html` (SPA shell) + `data/*.zip` (per-test
  payloads: trace + attachments) + `trace/` (embedded trace viewer SPA).
  No server required; `npx playwright show-report <dir>` serves it.
- Hash-URL routing: `#?` (All), `#?q=s%3Apassed|failed|flaky|skipped`
  (status filters), `#?speedboard` (slowest tests), `#?testId=<id>`
  (open one test), `#?speedboard=&testId=<id>`. Back/forward works.
- Dark theme throughout (near-black background, white text, gray secondary,
  green/red/amber status accents).

### 2. Toolbar (top, sticky)
- Search box ("Search tests") with magnifier icon — live-filters test rows
  by title as you type (the `/` key focuses it in the real app).
- Status filter chips with count badges: `All`, `Passed` (green check),
  `Failed` (red cross), `Flaky` (amber warning), `Skipped` (circle-slash).
  Active chip highlighted; chips are links (hash routing).
- Right side: `Speedboard` link (clock icon) and `Settings` button (gear).

### 3. Metadata row
- Run timestamp and `Total time: 19.3s` (right-aligned, gray).

### 4. Test list (overview)
- Tests grouped by file; group header = file name with chevron (collapsible).
- One row per test: status icon; bold title; right-aligned duration
  (`10.4s`, `491ms`); sub-line `file.js:line`; filmstrip icon (screenshots
  exist); `View Trace` link when a trace exists (grayed/absent otherwise).
- Thin separators between rows.

### 5. Expanded test detail
- Header row: title, `file:line`, duration, `View Trace`.
- **Run / Retry #N tabs** — one tab per attempt (present when the test
  retried); each tab shows its own duration and content.
- **Errors** section (collapsible, only when failed): monospace error block —
  message, locator, expected/actual, timeout, call log — then a source
  excerpt (5 lines around the failure) with the failing line highlighted and
  a `>` caret, then `at file.js:42:50`.
- **Test Steps** tree (collapsible): `Before Hooks`, each step
  (name, `file:line`, duration, status icon), `After Hooks`,
  `Worker Cleanup`. Steps with children expand; failed steps highlighted.
- **Screenshots** section: attachment names as links; clicking opens the
  **image viewer** modal: full-size image, zoom, before/after filmstrip for
  pairs, Esc/click-outside closes.
- **Traces** section: trace file links (we have no traces — omitted).
- **Attachments** section: other attached artifacts (e.g. error-context).
- Footer line: `Executed in Worker #0`.

### 6. Speedboard
- `Slowest Tests` panel, tests sorted by duration (descending), each row a
  duration bar + title link (opens the test) + `file:line` + duration.

### 7. Out of scope for EinkHome
- Trace viewer SPA (no trace data exists; the screenshot filmstrip + steps
  tree is our equivalent).
- Per-test retries (the suite has none) — keep the data model (attempts
  array) so retry tabs render when retries ever exist, but they will be
  absent in practice.

## EinkHome mapping

| Playwright | EinkHome |
|---|---|
| test file grouping | `tests/test_bookshelf.py`, `tests/test_bookshelf_scale.py` |
| test | pytest item (title, file:line, outcome, duration) |
| steps | the SnapshotRecorder capture list: label + PNG + elapsed ms |
| screenshots attachments | our PNGs (per-test dir `build/screenshots/<test>/`) |
| error | pytest failure text + traceback tail |
| run metadata | timestamp, total wall time, firmware name, git commit |
| show-report | `scripts/gen_report.py` (generate) + `--serve` (http server) |

## Data contract (results.json)

Written by the collector plugin to `build/report/results.json` after the
suite finishes; consumed by `scripts/gen_report.py`.

```jsonc
{
  "generated_at": "2026-08-12T10:00:00+00:00",   // ISO
  "total_time_s": 482.1,                          // wall time of the run
  "firmware": "U634k3_6.10.2544",                 // PB_TEST_FIRMWARE or ""
  "commit": "f1014dd",                            // git rev-parse --short HEAD
  "tests": [
    {
      "id": "tests/test_bookshelf.py::test_x",    // unique, stable
      "file": "tests/test_bookshelf.py",
      "line": 212,
      "title": "test_x",
      "status": "passed",                         // passed|failed|skipped
      "duration_s": 12.34,
      "started_at": 1784645047.12,                // epoch seconds (float): setup-phase call.start (session anchor fallback)
      "finished_at": 1784645107.88,               // epoch seconds (float): teardown-phase call.stop
      "error": "full failure text or null",       // incl. traceback tail
      "log_open_start": 7,                        // bookshelf invocation ordinals
      "log_open_end": 8,                          // (slice = markers [start, end))
      "attempts": [                               // one entry per run; >1 if retried
        {
          "status": "passed",
          "duration_s": 12.34,
          "steps": [
            { "label": "boot", "png": "screenshots/test_x/000-boot.png", "ms": 2345 }
          ]
        }
      ]
    }
  ]
}
```

- `png` paths are relative to `build/report/` (the generator copies each
  per-test screenshot PNG into `build/report/screenshots/<test>/NNN-label.png`
  preserving the original names and order from `index.txt`).
- Steps come from the SnapshotRecorder's per-test capture list (label + file
  name + wall-clock ms since test start). The recorder must expose that list.
- Per-test bookshelf.log scopes are cut at invocation-marker boundaries
  using `log_open_start`/`log_open_end` (ordinals recorded by the suite
  fixtures), so adjacent tests never share lines; the api.log slice uses the
  `started_at`/`finished_at` time window (±1s, midnight-wrap safe). Old
  results without the ordinal fields fall back to the time window.
- Logs are not in results.json; the generator copies the shared full logs
  `pbemu/<firmware>/.live/var/log/system.log`, `monitor.log`, `informer.log`
  (and the full bookshelf.log) into `build/report/logs/` (best-effort — they
  have no timestamps and cannot be sliced) and, per test, slices the current
  bookshelf.log and `build/pbemu-api-test.log` by their `[HH:MM:SS]` prefixes
  against the window `[started_at-3s, finished_at+3s]` (seconds-of-day, with
  a 86400s offset when the window crosses midnight) into
  `build/report/logs/<test>/bookshelf.log` and `api.log` — each prefixed with
  a `# scoped to <title> [start .. end]` header line. Fallbacks: a test
  without a usable `started_at`/`finished_at` (e.g. reports generated from an
  older results.json) links only the shared full logs, and a source log
  without any timestamped lines (old format) is copied in full instead of
  sliced. Each test's Logs section lists its scoped files first, then the
  shared full logs.

## Files to produce

- `tests/support/bookshelf/report.py` — pytest plugin (registered in
  `tests/conftest.py` via `pytest_plugins` or direct hook imports):
  session-start/finish timing, per-test report collection (makereport),
  step harvesting from the SnapshotRecorder, results.json writer.
- `scripts/gen_report.py` — static HTML generator: reads results.json,
  copies screenshots + logs, emits `build/report/index.html` (+ inline
  CSS/JS, no external assets), implements hash routing, chips, search,
  speedboard, expandable tests, image viewer, dark theme. CLI:
  `gen_report.py [--results build/report/results.json] [--out build/report]`
  and `gen_report.py --serve [--port 8901]` (http.server + open).
- Workflow: e2e-suite.yml gains a step after the suite run that always runs
  `pbemu/.venv/bin/python scripts/gen_report.py` (guarded by "report dir
  exists") and uploads `build/report/` as an artifact `e2e-report`
  (`if: always()`, retention 14d).
